# DEF-041 — Research turns a model-labelled recall on any official domain into a recall carrying this product's own name

Found by security-auditor on 2026-11-22 (WO-017) · Owner: data-ai-engineer · Severity: S3
Status: FIXED-PENDING-QA

## What happens
`backend/app/modules/research/service.py:174,195-196`, `web.py:26-28,53-57`: the recall row gets the product's own name and brand, so screening (`screening/service.py:109-119`) produces a guaranteed `near_match`, a needs-information badge and recall alerts even when the notice only names the brand. Any `*.gov.uk`/`*.canada.ca` subdomain counts as official.

## What should happen
The recall stores the product name the notice prints; linking needs the model number or a name match in the page text; regulator hosts narrowed to an explicit list.

## Repro
Read the cited lines on `week-02` @ 706b0f8.

security-auditor S-2 (Medium). Full record: `verdicts/WO-017-security.md`.

## Fix
data-ai-engineer, 2026-11-22, worktree `wt-w2-gaps` (branch `wt/w2-gaps`).
- `backend/app/modules/research/web.py`: `official()` now trusts only the registries that build their own URLs (`uk_opss`, `openfda`) or a page whose host (minus `www.`) is exactly one of `REGULATORS`; the wildcard suffix match and the `regulator_web`-tag bypass are gone; `canada.ca` and `gc.ca` dropped (only `recalls-rappels.canada.ca`). New `name_in_page()` and `printed_name()`.
- `backend/app/modules/research/service.py` `_official_recall`: a notice becomes a recall only when it prints this product's model number or every distinctive word of its name; `recall_products.product_name` is the name the notice prints; `brand_name` only when the notice names the brand.
