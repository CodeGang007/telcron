# DEF-060 — schema_spec.py still requires a verified phone for Level 1; the database does not

Found by database-engineer on 2026-11-22 (WO-022) · Owner: database-engineer · Severity: S4
Status: FIXED-PENDING-QA

## What happens
`docs/database/schema_spec.py:244` declares `users_chk3` as
`verification_level = 0 OR (email_verified_at IS NOT NULL AND phone_verified_at IS NOT NULL)`.
Migration `db/migrations/20261121120000_level1_email_only.sql` (ADR-006) replaced it in the database with
`verification_level = 0 OR email_verified_at IS NOT NULL`. The spec, the generated catalogue in
`docs/database/schema-design.md` and the ERD therefore describe a rule the database no longer has, and the
spec is the top of the source ranking in `telcron-business-rules`.

## What should happen
The spec states the rule the database enforces. Fixing it is not a one-line edit: the spec also generates
the already-applied `20261114120200_phase1_schema.sql`, which must not change. The generator needs a way to
express "changed after this migration" (e.g. a per-check `since=` that keeps the old text in the frozen
phase-1 file and puts the new one in a delta migration), or the frozen phase files stop being regenerated.
The same question now applies to phases 2-3 (frozen by WO-022).

## Repro
`grep -n users_chk3 db/migrations/*.sql docs/database/schema_spec.py`

## Evidence
`docs/database/schema_spec.py:244`, `db/migrations/20261114120200_phase1_schema.sql:36`,
`db/migrations/20261121120000_level1_email_only.sql:6-8`. The drift test does not compare CHECKs, so it is green.

## Fix
By database-engineer on 2026-11-22, branch `wt/db-fix`.
- `docs/database/schema_spec.py`: new `Revised(now, applied=, by=)` check type. `users_chk3` is now
  `Revised("verification_level = 0 OR email_verified_at IS NOT NULL", applied=<old text>,
  by="20261121120000_level1_email_only.sql")`. The catalogue and the ERD show the current rule.
- `docs/database/tools/build_sql.py`: a `Revised` check is written into its phase migration with its `applied`
  text, so `make db-gen` regenerates every migration byte for byte; only `schema-design.md` (one line) and
  `telcron-erd.drawio` (the users box, 4 places) change.
- CHECK comparison added (cheap, so done) as a schema test, not in the backend drift test (CHECKs are not in
  the mapping): `db/tests/test_spec_checks.py`. Each spec check is added to an empty `LIKE` copy of its table and
  PostgreSQL's deparsed text is compared with the live `<table>_chkN` constraint, both directions. A second
  test holds each `Revised` to its migration (the `by` file adds the new text; the phase SQL keeps the old).
  Revert proof: with the old spec both tests fail; the first reports exactly `users_chk3`, the only divergence.
- Not covered: CHECKs written by hand outside the spec (e.g. `chat_messages_chk*` come from the spec too and
  match); exclusion constraints and constraint triggers are still not compared.
