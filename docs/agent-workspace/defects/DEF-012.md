# DEF-012 — "Dismiss" closes a task but leaves its subject stuck: coins frozen for good, a flag pending for good

Found by qa-test-engineer (WO-017, part A) on 2026-11-22 · Owner: community-rewards-engineer (WO-006's owner) · Severity: S3
Status: OPEN

## What happens
`resolve()` (`backend/app/modules/moderation/service.py:187`) skips every subject handler when the decision is
`dismiss`, then marks the task `dismissed`. The web queue offers Dismiss on every task
(`frontend/src/pages/ReviewQueue.tsx:84`).
- `fraud_hold` dismissed: the hold stays `open` and its coins stay `frozen`. No open task points at it any
  more, so nothing in the product can release or confirm it.
- `hazard_flag` dismissed: the flag stays `pending`. The reporter can never file another flag on that
  product, because `POST /products/{id}/flags` refuses while one is pending
  (`backend/app/modules/community/router.py:131-134`, `409 flag_pending`).
- `fact_report` dismissed: the report stays `pending` (it is shown as such on the member's rewards page).

## What should happen
Either a dismissal moves the subject to a final state (a dismissed flag becomes `rejected` with no trust
penalty, or a matching status if the schema has one, and a report the same), or `dismiss` is refused
for task types whose subject needs a decision (`fraud_hold`). Which one is the owner's call, with tech-lead.

## Repro
Read from the code paths above; not exercised end to end. The fraud-hold case follows directly from
`coin_resolve_hold` never being called. No test covers `dismiss` (`grep -n dismiss backend/tests` → nothing).

`backend/app/modules/moderation/service.py:184-195`; `backend/app/modules/moderation/router.py:17`
