# DEF-024 — Member photos are stored as sent: no server-side safety check or location-data removal

Found by qa-test-engineer on 2026-11-22 (WO-017, verdict on WO-014) · Owner: catalogue-engineer · Severity: S3
Status: OPEN

## What happens
`POST /identify/photo` and confirm store each data-URL image's bytes in the media bucket unchanged
(`backend/app/modules/catalogue/identify.py:268` → `photos.store`, `backend/app/modules/catalogue/photos.py:44-48`).
The only checks are a data-URL regex on the declared type and 5,000,000 characters per image
(`router.py:58`). EXIF (GPS) is removed only because the web app re-encodes through a canvas
(`frontend/src/components/IdentifyNew.tsx:27`); any other API client stores the original file with its location.
No safety check runs. Confirmed photos become the product's public pictures (5-minute presigned links).

## What should happen
`telcron-security`: "Images pass a safety check and have location data removed before storage." Server-side:
decode, verify the real type, strip metadata (re-encode), then store; a safety check before a photo is shown publicly.
WO-014 "Open" names only "Photos are not moderated".

## Repro
POST a JPEG with GPS EXIF as a data URL (no canvas) to `/identify/photo` then confirm; the object in the bucket
carries the EXIF block. (Read from code; not run against S3 — no AWS this run.)
