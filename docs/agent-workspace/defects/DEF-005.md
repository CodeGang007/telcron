# DEF-005 — Two schemas for one database; the backend's enum values are wrong

Found 2026-11-15 while preparing the first push · Owner: database-engineer · Severity: S2
Status: OPEN

## What happens
`backend/app/models/enums.py` holds values inferred from the technical documentation. The real ones are
on branch `feat/database-schema`. Of 61 enum types, 54 differ. Examples: `user_role` is
`user, moderator, admin` there and `user, safety_reviewer, admin, business` here; `auth_provider` there
is `google, facebook, apple` (no `password`); `traceability_status` there is
`pending, traced, untraceable` and here `unknown, partial, verified`. The backend also re-implements in
Python the coin and append-only rules that branch enforces in the database.

## What should happen
One schema, generated from `docs/database/schema_spec.py`, and a backend that maps onto it.

## Evidence and state
Compared by script: enum definitions parsed from that branch's SQL against the SQLAlchemy `Enum`
objects here. The backend works against its own schema (20 tests pass) and would not work against the
designed one. Fix is WO-011.
