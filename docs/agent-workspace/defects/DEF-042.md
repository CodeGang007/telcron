# DEF-042 — Anonymous GET starts outside calls (Tavily, LLM) inside the API and can drain the shared allowance

Found by security-auditor on 2026-11-22 (WO-017) · Owner: data-ai-engineer · Severity: S3
Status: FIXED-PENDING-QA

## What happens
`backend/app/modules/research/router.py:39-46`, `market.py:73-110`: an anonymous request calls Tavily and the model in the API process (breaks "only the Worker calls out"); ~60/day anonymous ≈ 1,800/month against a 1,000 plan.

## What should happen
Anonymous callers get cached results only; starting a search or a market lookup needs sign-in (Level 1 where research already requires it).

## Repro
Read the cited lines on `week-02` @ 706b0f8.

## Evidence
security-auditor S-3 (Medium). Moving the call fully into the Worker is noted for WO-035 (W5); this defect is the access fix. Full record: `verdicts/WO-017-security.md`.

## Fix
data-ai-engineer, 2026-11-22, worktree `wt-w2-gaps` (branch `wt/w2-gaps`).
- `research/router.py`: GET `/marketplace` takes `OptionalUser`; anonymous gets the cache only with `reason: "not_authenticated"`, a signed-in Level 0 member `reason: "verification_level_1_required"` (same level as POST research); a verified member searches in the API process as before (Worker move stays WO-035/W5). GET `/research` passes `signed_in`.
- `research/market.py`: `listings(..., refused)` returns the cache or the refusal, never calls Tavily or the model.
- `research/service.py`: `blocked(ask_provider=)`; an anonymous summary reads the search balance from the Redis cache only (`_cached_searches_left`), so it never calls Tavily's usage endpoint. POST research already required Level 1 (401 anonymous, unchanged).
- Tests: `test_an_anonymous_visitor_sees_cached_listings_only_and_starts_no_search`, `test_an_anonymous_research_view_never_asks_the_provider` (also asserts POST anonymous -> 401 `not_authenticated`). Two existing tests now call as a member.
