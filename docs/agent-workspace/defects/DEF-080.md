# DEF-080 — Text search scans every product: 230–400 ms at 50 000 products

Found by qa-test-engineer on 2026-11-22 (WO-017 final QA, part A) · Owner: catalogue-engineer · Severity: S3
Status: OPEN

## What happens
`GET /api/v1/products?q=<text>` (no barcode or model-number hit) ranks with
`word_similarity(q, canonical_name) > 0.35 OR canonical_name ILIKE '%q%' OR brand ILIKE '%q%'`,
ordered by that similarity (`backend/app/modules/catalogue/service.py:77-84`). Neither form can use the
GiST trigram index `products_i1_idx`, so PostgreSQL reads every product row on every search. The time grows
with the catalogue. `telcron-performance` already lists this under "Known, not yet fixed", but no defect or
work order tracks it.

## What should happen
The fuzzy branch uses the KNN form the index serves (`ORDER BY canonical_name <-> :q LIMIT n`, plus the brand)
as `telcron-performance` says, and the read stays index-backed as the catalogue grows. The schema's own perf case
"Fuzzy product search (trigram)" (`db/tests/test_performance.py`) already uses that form: 19.73 ms at 100 000
products. The application does not.

## Repro
1. Lane DB built with `dbmate up` + `001_core_reference.sql` + `db/seeds/dev/sample_data.sql`, then 50 000
   synthetic products (`INSERT ... SELECT generate_series(1, 50000)`, names like "Power Bank Ultra 123"), `ANALYZE`.
2. API from `wt/qa-final-a` @ 838beea (`uvicorn app.main:app`, no embedder configured, so search uses words only).
3. `curl -w '%{time_total}' 'http://127.0.0.1:<port>/api/v1/products?q=power%20bank%20ultra'`, 30 times.

## Evidence
HTTP, 30 runs each, measured on its own (nothing else running):
```
search q=blender            p50=233.7ms p95=273.2ms max=301.9ms
search q=blendr (typo)      p50=237.2ms p95=262.8ms max=272.4ms
search q=power bank ultra   p50=358.6ms p95=401.0ms max=401.2ms
search q=QA-12345 (model)   p50=11.9ms  p95=12.7ms  max=13.2ms    <- exact branch, index-backed
```
The same query in SQL, `EXPLAIN (ANALYZE)`:
```
->  Seq Scan on products p (actual time=0.021..22.970 rows=50004.00 loops=1)
Rows Removed by Filter: 40105
Execution Time: 375.267 ms
```
The KNN form on the same data: `Index Scan using products_i1_idx on products` · `Execution Time: 4.494 ms`.
The cached passport read is fine (p50 6.4 ms). This is search only. Search is the first thing a visitor does,
and the time grows with the catalogue.
