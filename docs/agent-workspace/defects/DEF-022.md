# DEF-022 — Assistant: a malformed thread_id is an unhandled ValueError (500)

Found by qa-test-engineer on 2026-11-22 (WO-017, verdict on WO-015) · Owner: data-ai-engineer (`modules/assistant` has no owner in `telcron-domain-map`; see DEF-023) · Severity: S4
Status: FIXED-PENDING-QA

## What happens
`POST /api/v1/products/{slug}/assistant` with `{"message": "hello there", "thread_id": "not-a-uuid"}` from a
Level 1 member raises `ValueError: badly formed hexadecimal UUID string` at
`backend/app/modules/assistant/chat.py:87` (`uuid.UUID(thread_id)`); `AskIn.thread_id` is a plain `str`
(`backend/app/modules/assistant/router.py:14`). In the app this is a 500.

## What should happen
422 (type the field as `uuid.UUID | None`) or 404 `thread_not_found`, as for another member's thread.

## Repro
A throwaway test in the `wt-qa-b` worktree (deleted after): signed-in member, the request above →
`RAISED ValueError badly formed hexadecimal UUID string`.

## Evidence
`backend/app/modules/assistant/chat.py:84-90`.

## Fix
By data-ai-engineer, 2026-11-22. Chose **422**, the API's existing validation shape: every other id the API takes
(path or body) is declared `uuid.UUID` (`community/router.py:113`, `wallet/router.py:77`,
`moderation/router.py:29`, `screening/router.py:18`), so a malformed one is FastAPI's 422 there too.
- `backend/app/modules/assistant/router.py`: `AskIn.thread_id: uuid.UUID | None`.
- `backend/app/modules/assistant/chat.py`: `_thread` and `ask` take `uuid.UUID | None`; the `uuid.UUID(thread_id)`
  parse is gone. Another member's well-formed thread is still 404 `thread_not_found`.
- Test: `backend/tests/test_assistant.py::test_a_malformed_thread_id_is_a_validation_error_not_a_crash` (422,
  `loc == ["body", "thread_id"]`).
- Revert proof: with the two app files reverted the test fails with
  `ValueError: badly formed hexadecimal UUID string` (`1 failed, 5 deselected`); restored, it passes.
- Gate (lane 55445/63845): `ruff check .` → `All checks passed!`; `pytest -q` → `135 passed, 4 warnings in 25.14s`.
