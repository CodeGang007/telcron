# DEF-031 — No way to vote a review helpful in the web app

Found by browser-qa-engineer on 2026-11-22 (WO-017 run 2, local stack @ 706b0f8) · Owner: frontend-engineer · Severity: S3
Status: FIXED-PENDING-QA

## What happens
Journey 4 (`telcron-user-flows`: review, **helpful vote**, hazard flag) lists the helpful vote as built.
The API has it (`POST /api/v1/reviews/{id}/helpful`: 204, a repeat is idempotent, own review → 409
`own_review`, no token → 401, all verified by curl this run). The product page renders reviews with no
control to vote; it only shows "N found this helpful" when the count is above zero.

## What should happen
A signed-in Level 1 member sees a "Helpful" control on other members' reviews (not their own), it reflects
their vote after reload, and a visitor is offered sign-in.

## Repro
1. Sign in as a Level 1 member, open `/products/northwind-chillmate-31`, scroll to Reviews.
2. No button on any review (`li` elements in the Reviews section contain no `button`).

## Evidence
- `frontend/src/pages/Product.tsx:391` is the only use of `helpful` in `frontend/src/pages`; no call to `/helpful`
  anywhere in `frontend/src` (`grep -rn helpful frontend/src`).
- API check: two votes by the same member on "Demo User"'s review → `helpful_count` 1 (paid/counted once).

## Fix
frontend-engineer, 2026-11-22, on `week-02` @ 3e99ad4 (uncommitted).
`frontend/src/components/Reviews.tsx` (review list moved out of `Product.tsx`, which was over 400 lines): a
"Helpful" button (44 px high) on every member review; visitors get "Sign in to vote helpful", members below Level 1
"Confirm your email to vote helpful". After a 204 it reads "You found this helpful" and the count goes up by one.
409 `own_review` hides the button and says "You cannot vote on your own review." (`MESSAGES`, plus `review_not_found`).
Limit: `GET /products/{id}/reviews` does not say whether the caller wrote a review or already voted, so the
own-review state appears only after a click, and the voted state survives a reload only in the same browser
(kept in localStorage per member). Backend request (community owner): add `mine: bool` and `voted: bool` to
`ReviewOut` for a signed-in caller; the web app already reads both (`Review.mine`, `Review.voted` in `api.ts`).
Gate: `npx tsc --noEmit` 0 errors; `npm run build` built. Browser walk not run (stack was not up).

Back half: community-rewards-engineer, 2026-11-22, on `week-02` @ c57aa26 (uncommitted).
`backend/app/modules/community/router.py` `list_reviews` takes `OptionalUser`; `ReviewOut` gains `mine` and `voted`
(both false for a visitor). The caller's votes on the page come from one query
(`review_votes WHERE user_id = caller AND review_id IN (page)`), so no N+1. Test
`backend/tests/test_reviews.py::test_the_review_list_marks_the_callers_own_review_and_votes` (visitor, author, voter);
red with the fields forced to false, green restored. Gate: ruff clean, `143 passed in 32.80s`. Browser walk not run.
