## Blocked on human
One decision for the remaining occurrences (not changed, outside this fix's scope):
`infra/aws/deploy-host.sh:11,12,28`, `infra/aws/db-lib.sh:10`, `infra/aws/setup-backend-host.sh:7,8,105,106`,
`infra/aws/migrate-from-rds.sh:41`, `backend/app/core/config.py:74`,
`.claude/skills/telcron-infrastructure/SKILL.md:24,42`.
- **A (recommended): keep them as functional names, recorded in an ADR.** A region and a secret's name are not
  identifiers of an account or a resource instance (no account id, ARN, address); the scripts need working
  defaults to be run by hand through Session Manager, and the host's IAM policy is what protects the secret.
  The ADR states the rule: names may appear, ids/ARNs/addresses never. Cost: none. Owners: infra (scripts),
  backend (config), tech-lead (skill).
- **B: parameterise.** Remove the defaults; `deploy-host.sh`/`setup-backend-host.sh` take `APP_SECRET_ID` and
  `AWS_REGION` only from the host's `deploy.env` (written at set-up), `db-lib.sh` from the instance metadata
  (`/latest/meta-data/placement/region`), `config.py` default becomes empty, the skill says "the app secret".
  Cost: none, but the running host's `deploy.env` must be checked to hold both values before the push, or the
  next release fails.
