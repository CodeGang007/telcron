# DEF-014 — A reload drops the pages already loaded in a list

Found by qa-test-engineer (WO-017, part A) on 2026-11-22 · Owner: frontend-engineer · Severity: S4
Status: FIXED-PENDING-QA

## What happens
WO-012's acceptance says "Search and lists paginate; reload keeps the page." Lists page with "show more":
`frontend/src/lib/usePaged.ts` always loads offset 0 on mount (`reload` → `apiPage(path, 0, pageSize)`) and
appends with `more()` using `items.length`. The page reached is kept only in component state, not in the
URL. After two "show more" clicks on `/search?q=…`, `/recalls`, `/wallet` or the rewards lists, a reload
goes back to the first 12 items. The search query itself survives (`pages/Search.tsx:11`, `useSearchParams`).

## What should happen
One of these, decided with tech-lead:
(a) keep the depth in the URL (e.g. `?n=36`) and load that much on mount, so reload and back keep the place; or
(b) change the acceptance to "reload keeps the query" if infinite "show more" is the intended design.

## Repro
Read from `frontend/src/lib/usePaged.ts:13-33` and its five callers (`pages/Search.tsx`, `Recalls.tsx`,
`Wallet.tsx`, `Rewards.tsx`, `Product.tsx`). Not walked in a browser by this finder (that is browser-qa's lane).

## Evidence
`usePaged.ts:24` `const page = await apiPage<T>(path, 0, pageSize);`. No URL parameter for the offset anywhere
in `usePaged.ts`.

## Fix
By frontend-engineer on 2026-11-22, branch `wt/frontend`, commit `fac9987`. Status: FIXED-PENDING-QA

Option (a), the depth is kept, but in **sessionStorage, not the URL**. `src/lib/usePaged.ts` stores the
number of items shown under `telcron.paged:<location.key>:<api path>` after each "show more", and on mount
loads that many again (requests of at most 50, the smallest endpoint maximum; capped at 200 items).
Why: React Router keeps `location.key` in `history.state`, so the depth survives a reload and back/forward
exactly as a URL parameter would, while a fresh visit to the same address starts at the top, shared links
stay clean, and pages with two lists (Rewards, Product reviews) need no extra parameters. No caller changed.
