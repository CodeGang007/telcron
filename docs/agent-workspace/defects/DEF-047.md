# DEF-047 — Deployment hardening: backups deletable by the host, admin seed password on a command line, actions pinned by tag

Found by security-auditor on 2026-11-22 (WO-017) · Owner: infra-deploy-engineer · Severity: S4
Status: FIXED-PENDING-QA (S-9, S-11) · backups (S-8) PREPARED — BLOCKED ON HUMAN

## What happens
`backup-db.sh:21,40-48` same bucket, host role can delete; `deploy-host.sh:156` `-e SEED_ADMIN_PASSWORD=…` visible in the process list; `pipeline.yml:28-30` actions pinned by tag.

## What should happen
Seed password passed by name only; actions pinned to commit SHAs; backups protected (versioning/Object Lock + lifecycle instead of DeleteObject) — the S3/IAM part prepared for the human with cost.

## Blocked on human
**S-8 — the host can delete its own backups.** Prepared, nothing applied. `infra/aws/backup-db.sh:40-48` deletes
dumps older than 14 days with the host role's `s3:DeleteObject` on the raw bucket. Placeholders: `<region>`,
`<raw bucket>`, `<host role>` (values in `aws-dev.local.md` / the console).

Recommended — **A: versioning + lifecycle + an explicit deny on the host role.** S3 expires the dumps; the host
can no longer delete or permanently overwrite one (an overwrite leaves the old version for 14 days).
Monthly cost: **about USD 0.00–0.05** (versioning and lifecycle are free; at worst 14 extra small dumps as
noncurrent versions, S3 Standard USD 0.023/GB-month; the inline policy is free).
1. Read first (read-only): `aws s3api get-bucket-lifecycle-configuration --region <region> --bucket <raw bucket>`
   — `put-bucket-lifecycle-configuration` replaces the whole configuration; merge any rule it prints.
2. `aws s3api put-bucket-versioning --region <region> --bucket <raw bucket> --versioning-configuration Status=Enabled`
3. `aws s3api put-bucket-lifecycle-configuration --region <region> --bucket <raw bucket> --lifecycle-configuration file://lifecycle.json`
   ```json
   {"Rules": [
     {"ID": "postgres-backups-14d", "Status": "Enabled", "Filter": {"Prefix": "backups/postgres/"},
      "Expiration": {"Days": 14}, "NoncurrentVersionExpiration": {"NoncurrentDays": 14},
      "AbortIncompleteMultipartUpload": {"DaysAfterInitiation": 1}},
     {"ID": "postgres-backups-delete-markers", "Status": "Enabled", "Filter": {"Prefix": "backups/postgres/"},
      "Expiration": {"ExpiredObjectDeleteMarker": true}}]}
   ```
   (`backups/rds-final/` is outside the prefix and is kept.)
4. Push a change to `infra/aws/backup-db.sh` (infra-deploy-engineer, prepared on request): drop lines 40-48 (the
   clean-up loop), keep `KEEP_DAYS` out, and change header line 9 to "s3:PutObject and s3:ListBucket; S3 expires
   old backups (lifecycle rule)". This must be live **before** step 5, or the nightly run fails at the delete.
5. `aws iam put-role-policy --role-name <host role> --policy-name telcron-dev-backups-no-delete --policy-document file://deny.json`
   ```json
   {"Version": "2012-10-17", "Statement": [{"Sid": "HostCannotRemoveBackups", "Effect": "Deny",
     "Action": ["s3:DeleteObject", "s3:DeleteObjectVersion", "s3:PutLifecycleConfiguration",
                "s3:PutBucketVersioning", "s3:PutBucketPolicy", "s3:DeleteBucketPolicy",
                "s3:PutBucketObjectLockConfiguration"],
     "Resource": ["arn:aws:s3:::<raw bucket>", "arn:aws:s3:::<raw bucket>/backups/*"]}]}
   ```
   An explicit deny wins over whatever the role's existing policy allows, so its JSON need not be edited.
6. Check: run `backup-db.sh` by hand (passes, one object written); `aws s3api list-object-versions` on the prefix
   shows versions. Update `docs/runbooks/aws-dev.md` (Backups section, the bucket and role rows) in the same change.
Rollback: `aws iam delete-role-policy --role-name <host role> --policy-name telcron-dev-backups-no-delete`;
`aws s3api delete-bucket-lifecycle --bucket <raw bucket>` (or put back the merged old rules); revert
`backup-db.sh`. Versioning cannot be turned off, only suspended (`Status=Suspended`).

Alternative — **B: Object Lock** (governance mode, default retention 14 days) on top of A's versioning:
`aws s3api put-object-lock-configuration --bucket <raw bucket> --object-lock-configuration
'{"ObjectLockEnabled":"Enabled","Rule":{"DefaultRetention":{"Mode":"GOVERNANCE","Days":14}}}'`. Same cost as A.
Not recommended now: default retention applies to the whole bucket (not a prefix), so any future raw copies in
that bucket become undeletable for 14 days, and Object Lock cannot be removed from a bucket once enabled. A's
explicit deny already stops the host.
