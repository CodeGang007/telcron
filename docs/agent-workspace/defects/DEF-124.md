# DEF-124 — Home hero is wider than a 390 px phone: headline, intro and Search button are cut off

Found by browser-qa-engineer on 2026-11-23 (WO-058 browser verification, local stack @ 80f18b2) · Owner: frontend-engineer (`frontend/src/pages/Home.tsx`, `frontend/src/components/SearchBox.tsx`) · Severity: S3
Status: FIXED — browser QA PASS 2026-11-23 (4f16d8a)

## What happens
At 390 px the home hero's grid column is 429 px wide inside a 389 px viewport. The section has `overflow-hidden`,
so there is no horizontal scroll (`scrollWidth` = viewport) but the content is clipped on the right: "Know what's
saf|e", the intro paragraph and the "Search" button of the hero search box are cut off. Not a WO-058 regression
(SearchBox last changed in DEF-013, aa293fe); `scrollWidth` checks do not catch it, which is why earlier sweeps passed.

## What should happen
Every hero element fits inside 390 px (business rule: phone first, no horizontal scroll and nothing clipped).

## Repro
1. `make dev`; open `http://localhost:3200/` at 390 × 844.
2. Look at the hero, or in the console: `document.querySelector('h1').getBoundingClientRect().right` → 445 (viewport 389).

## Evidence
- Ancestors of the `h1`: `DIV.container-page relative grid … lg:grid-c…` w=389 has `grid-template-columns: 429.2px`;
  its first child (text column) is 429 px, `min-width: auto`.
- Hiding the hero search block (`div.mt-10.flex.flex-col …`) drops the column to 356.8 px; setting the search
  `<input>` width to 0 does the same. So the input's intrinsic width (no `size`/`w-0`; `min-w-0` does not help in a
  column flex parent) sets the grid item's min-content width. Likely fix: `min-w-0` on the grid item or `w-0`/`size={1}`
  on the input — the owner decides.
- `/search` at 390 px: nothing overflows (the box is fine there).
