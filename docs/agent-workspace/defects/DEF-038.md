# DEF-038 — Wallet "Remove" is invisible on a phone (hover-only) and is a 32 px target

Found by browser-qa-engineer on 2026-11-22 (WO-017 run 2, local stack @ 706b0f8) · Owner: frontend-engineer · Severity: S3
Status: FIXED-PENDING-QA

## What happens
Each wallet card's remove button has `opacity-0 … group-hover:opacity-100 focus:opacity-100`. On a touch
screen there is no hover, so at 390 px the card shows no remove control at all (computed opacity 0). The button
is still there, 32×32 px at the card's top right, so a tap there removes the product with no confirmation and
no undo. Nothing tells the member it is possible.

## What should happen
Remove is visible on touch devices (or behind a visible menu), at least 44×44 px, and removal can be undone
(toast "Undo") or is confirmed in-page (not `window.confirm`).

## Repro
Open `/wallet` as a member with one saved product, 390×844 with touch. Look for a way to remove it.

## Evidence
- `frontend/src/pages/Wallet.tsx:44`.
- Playwright at 390 px, touch: `remove opacity on phone: 0 box {"x":321,"y":637.5,"width":32,"height":32}`;
  screenshot of the card shows no control.
- Desktop: hover reveals it; one click → `DELETE /wallet/items/{id}` 204, card gone, empty state
  "Your wallet is empty · Find a product you own"; survives reload.

## Fix
frontend-engineer, 2026-11-22, on `week-02` @ 3e99ad4 (uncommitted).
`frontend/src/pages/Wallet.tsx`: Remove is always visible, 44×44 px (`size-11`), labelled "Remove <name> from
your wallet". After removal the toast offers "Undo" for 8 s, which saves the product again and re-reads the wallet.
Gate: `npx tsc --noEmit` 0 errors; `npm run build` built. Browser walk not run (stack was not up).
