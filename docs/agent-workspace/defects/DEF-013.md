# DEF-013 — Literal colours in components: Tailwind palette, hex and rgb() outside the design tokens

Found by qa-test-engineer (WO-017, part A) on 2026-11-22 · Owner: frontend-engineer · Severity: S3
Status: OPEN

## What happens
WO-012's acceptance says "tokens only (no literal colours)", and so do CLAUDE.md's non-negotiables and
`telcron-frontend` ("No hex or literal colour in a component"). In `frontend/src` there are **49** uses
of Tailwind's built-in palette (`from-emerald-500`, `text-amber-600`, `to-rose-500`, ...) and **7** hex or
`rgb()` literals. None of them is a token from `src/index.css`.

## What should happen
Every colour comes from the `@theme` tokens in `src/index.css` (`brand*`, `action*`, `ok*`, `warn*`, `danger*`,
`gold*`, `ink`, `muted`, `line`, `panel`, `warm`, `night*`, `neutral-tint`). If the category tiles, podium and
stat-card gradients need more colours, add them as tokens.

## Repro
```
cd frontend/src
grep -rnoE "\b(bg|text|border|from|to|via|fill|stroke|ring|shadow)-(red|blue|green|yellow|gray|slate|zinc|stone|orange|amber|lime|emerald|teal|cyan|sky|indigo|violet|purple|fuchsia|pink|rose)-[0-9]{2,3}\b" --include=*.tsx . | wc -l   # 49
grep -rnE "#[0-9a-fA-F]{6}\b|rgb\(" --include=*.tsx . | wc -l                                                      # 7
```
