# DEF-121 — The e2e journey leaves its products and reviews in the shared local database and skews the demo passports

Found by browser-qa-engineer on 2026-11-23 (weeks 1-2 sweep, local stack @ 189a1c6, Worker running, COIN_CONFIRM_DELAY 15 s) · Owner: browser-qa-engineer (`e2e/journey.spec.ts`) · Severity: S4
Status: FIXED — QA PASS 2026-11-23 (4f66e92, 2cfd68e, 4c4020b); shared DB still holds old e2e rows (reset is the human's call)

## What happens
Each `npm run journey` run adds a "Lumina Test Desk Fan <timestamp>" product (`e2e/journey.spec.ts:259`) and posts
"The compressor started to overheat and there was smoke and a burning smell…" on Northwind (`:56`), and none of it
is removed. After the runs so far: 9 Lumina products, which fill the home page's "Fresh passports · Recently
screened" with six "Needs information / Not enough information yet" cards (they were not screened); Northwind has 13
passport versions, trust down from 96 to 81 and Health & Safety at 100, with the same 5-star complaint four times on
its first page of reviews. The demo products are what a person checks first, so later browser runs (and DEF-113) see
data shaped by the test suite. Also, the home heading "Recently screened" lists products that were never screened.

## What should happen
The journey cleans up after itself or runs against a disposable database (`make app-db` per run in CI is fine; the
shared local one is not), and does not post hazard reviews on the demo products. "Recently screened" lists products
that have a screening.

## Repro
1. `make app-db && make dev`, run `cd e2e && npm run journey` twice.
2. Open `http://localhost:3200/` and `/products/northwind-chillmate-31`.

- `select public_slug from products`: 9 rows `lumina-lumina-test-desk-fan-…` (2026-11-21/22).
- Home page text: six "Lumina Test Desk Fan … Needs information" cards under "Recently screened"
  (`frontend/src/pages/Home.tsx:156`).
