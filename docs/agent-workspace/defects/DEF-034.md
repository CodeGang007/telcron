# DEF-034 — Header coin balance stays stale after spending coins

Found by browser-qa-engineer on 2026-11-22 (WO-017 run 2, local stack @ 706b0f8) · Owner: frontend-engineer · Severity: S4
Status: FIXED-PENDING-QA

## What happens
After a redemption on `/rewards` the page's own balance updates (190 → 140, then 140 → 40), but the coin chip
in the header keeps the old number (190, then 140) until navigation or reload.

## What should happen
The header balance updates when coins are spent (or earned) on the current page.

## Repro
1. Sign in as a member with at least 100 confirmed coins, open `/rewards`.
2. Redeem "Watchlist alerts for 3 products". Header chip unchanged; "Spendable TelCoins" shows the new balance.

## Evidence
- `frontend/src/components/Layout.tsx:46-49` fetches `/coins` only when `me` or `location.pathname` changes.
  (Layout.tsx is tech-lead's for the navigation; the fix likely belongs in a shared balance hook or event.)
- API after the spend: `{"confirmed":140,…}` while the chip read 190.

## Fix
frontend-engineer, 2026-11-22, on `week-02` @ 3e99ad4 (uncommitted).
`frontend/src/lib/coins.ts` (`coinsChanged()`); called after a redemption (`Rewards.tsx`) and a review
(`components/Reviews.tsx`). `frontend/src/lib/auth.tsx` re-reads `/auth/me` on that event and when the tab becomes
visible again; the header chip's effect in `Layout.tsx` depends on `me`, so it reads `/coins` again. No change to
`Layout.tsx`. A failed `/auth/me` (network or 5xx) no longer signs the member out on screen.
Gate: `npx tsc --noEmit` 0 errors; `npm run build` built. Browser walk not run (stack was not up).
