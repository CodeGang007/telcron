# DEF-033 — Data sources page shows per-product research runs as 30-day CPSC-style runs, with garbled errors

Found by browser-qa-engineer on 2026-11-22 (WO-017 run 2, local stack @ 706b0f8) · Owner: frontend-engineer · Severity: S4
Status: FIXED-PENDING-QA

## What happens
`/data-sources` lists `web_search` jobs (one per product researched) as
"WEB_SEARCH · last 30 days · nightly" (trigger `schedule`) or "· by hand" (trigger `event`, which no admin
started), without the product, and prints the error list as "… · web: no search provider configured failed".
Three "nightly" runs at the same second look like a scheduler firing three times; they are three products.

## What should happen
A research run names its product and its real trigger (scheduled / on a review / by hand) and shows errors as
sentences. Or the page lists ingestion runs only, as its heading says.

## Repro
Sign in as admin, open `/data-sources` after any product research has run.

## Evidence
- `frontend/src/pages/DataSources.tsx:78-79` ("last 30 days" default, `trigger === 'schedule' ? 'nightly' : 'by hand'`),
  `:86` `${j.stats.errors} failed` with `errors` an array for `web_search` jobs (typed as `number` at `:13`).
- DB: `ingestion_jobs` web_search rows have `params = {"product_id": …}`, triggers `schedule`/`event`.

## Fix
frontend-engineer, 2026-11-22, on `week-02` @ 3e99ad4 (uncommitted).
`frontend/src/pages/DataSources.tsx`: two lists, "Recall imports" and "Product research runs". A research run
reads "Product research · open the product" (link by product id) with its real starter (automatic (new or due
product) / a member asked / an admin asked), its own figures (recall notices checked, web pages, findings), and each
error as a sentence ("Web search: no search provider configured."). Recall imports keep "nightly" / "by hand".
Backend nice-to-have (ingestion owner): include the product name in `job_view` for `web_search` jobs.
Gate: `npx tsc --noEmit` 0 errors; `npm run build` built. Browser walk not run (stack was not up).
