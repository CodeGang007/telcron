# CT-002 — GET /api/v1/products/{id_or_slug}/report

Status: FROZEN (2026-11-22, tech-lead) · Producer: community-rewards-engineer (`modules/rewards/router.py`) ·
Consumer: frontend-engineer (`frontend/src/pages/Report.tsx`) · Fixes DEF-035 (human chose reading (a), 2026-11-22)

## Caller
Signed in (`CurrentUser`), any verification level. The report is a paid entitlement: the caller must hold a
redemption with `status = 'fulfilled'` of an item whose `fulfilment_type = 'pdf_report'` and whose
`product_id` is this product, owned by the caller (`redemptions.user_id = caller`). A `refunded`, `failed` or
`processing` redemption does not count. Matching is on the item's fulfilment type, not the item code.

## Request
Path: `id_or_slug` — a product UUID or public slug (same resolver as `GET /products/{id_or_slug}`,
`catalogue.service.find_product`). No body, no query parameters.

## Response 200
```json
{
  "product":    { ...exactly the body of GET /products/{id_or_slug} (catalogue.service.product_detail) },
  "passport":   { ...exactly the body of GET /products/{id_or_slug}/passport (catalogue.service.passport_view) } | null,
  "redemption": { "id": "<uuid>", "fulfilled_at": "<ISO 8601>" }
}
```
`passport` is `null` when no passport is issued (not an error: the buyer still owns the report).
`redemption` is the caller's most recent qualifying redemption. Header `Cache-Control: private, no-store`.

## Errors
| Status | Code (`detail`) | When |
| --- | --- | --- |
| 401 | `not_authenticated` / `invalid_token` / `session_revoked` | no or bad bearer token (standard `CurrentUser`) |
| 404 | `product_not_found` | no product by that id or slug (checked before the entitlement) |
| 403 | `report_not_redeemed` | signed in, product exists, caller holds no qualifying redemption for it |

**Why 403 and not 404.** The 404-for-another-user's-row rule exists so a response never reveals that a row
belonging to someone else exists. Here the URL names a public product, not a redemption; the answer is identical
whether nobody or another member bought the report, so nothing about any other user is revealed. A missing
entitlement is a 403 like `verification_level_1_required`, and the distinct code lets the web app show
"Redeem for 50 TelCoins to unlock" instead of "not found". This endpoint never reads or names another user's
redemption.

## Side effects
None. Read only: no audit entry, no outbox event, no coins, no cache entry.

## Unchanged
- `GET /products/{id_or_slug}` and `GET /products/{id_or_slug}/passport` stay public (non-negotiable).
- `POST /redemptions` still records `fulfilment = {"report": "/products/<product id>/report"}` and answers
  `"report": "/products/<slug>/report"`: the fulfilment stays a link to the (now gated) page.
- `redemption_items.code = 'hazard_report_pdf'` does not change.
