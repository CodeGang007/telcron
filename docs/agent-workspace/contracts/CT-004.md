## POST /api/v1/redemptions — refusals (request and 201 body unchanged)
| Status | Code (`detail`) | When |
| --- | --- | --- |
| 401 | standard | no or bad token |
| 403 | `verification_level_1_required` | standard `Level1User` |
| 404 | `item_not_found` | no `redemption_items` row with that code |
| **409** | **`item_not_on_sale`** | the item exists and `is_active = false` (e.g. `watchlist_3`, the four D13 items). Checked by the server before any spend; `coin_redeem` refusing an inactive item (TC011) is the backstop and maps to the same code when the item exists. No ledger entry, no redemption row, balance unchanged. |
| 404 | `product_not_found` | unchanged |
| 422 | `product_required` | unchanged (only reached for an item on sale) |
| 409 | `not_enough_coins` | unchanged |
| 409 | `item_not_available` | unchanged (an on-sale item this service cannot fulfil, refunded in the same transaction) |

The web app shows for `item_not_on_sale`: "That reward is not on sale right now. Reload the page to see what is."
