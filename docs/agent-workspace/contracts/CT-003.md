# CT-003 — Honest passport, research and queue fields (DEF-113, 115, 118, 120, 121)

Status: FROZEN (2026-11-23, tech-lead) · Work order: WO-058
All changes are **additive**: no existing field is removed, renamed or changes meaning. Every consumer must
handle the new field being absent or `null` (cached passports, runs recorded before this change).

## A. `GET /api/v1/products/{id_or_slug}/passport` — producer catalogue-engineer (`catalogue/service.py: passport_view`)
New top-level field:
```json
"recall_checked_as_of": "<ISO 8601>" | null
```
= `screenings.corpus_synced_at` of the passport's screening (`passports.screening_id`); `null` when the passport
has no screening. Public, as today. The same object appears inside CT-002's `passport`, unchanged otherwise.

**Meaning (producer of the value: data-ai-engineer, `screening/service.py: screen_product`).** Business rule §4:
"no match found" is true as of the recall corpus date. `corpus_synced_at` must be the time Telcron's recall data
was last refreshed from the official source at or before the screening, not the screening's own clock: the
`finished_at` of the newest ingestion job that imported CPSC recalls and did not fail for CPSC (a scheduled/by-hand
import, or a product research run whose stats show CPSC answered), falling back to `now` only when no such job
exists (column is NOT NULL). The owner states the exact query in the WO log.

## B. `GET /api/v1/products/{id_or_slug}/research` — producer data-ai-engineer (`research/service.py`)
`stats` gains:
```json
"sources": { "<code>": "answered" | "failed" | "not_configured" }
```
Codes: `cpsc` (brand search), `uk_opss`, `openfda_<kind>` (only those called for the category), `web` (the open
web / owner-forum search provider), `reader` (the model that reads pages). `not_configured` = the provider is
not set up (e.g. web search with no key: the run never searched); `failed` = called and errored; `answered` = called
and returned (even with zero hits). A source not called for this product (e.g. no openFDA kind for the category, CPSC
when the product has no brand, everything except `reader` on a re-read) is absent. `stats.pages` counts only pages
from sources that answered (unchanged in practice). `errors` stays exactly as today (codes only, DEF-049); the
provider's text never reaches a response. Runs recorded before this change have no `sources` key: consumers fall
back to today's behaviour with neutral copy.

## C. `GET /api/v1/review-tasks` (and the single-task view, same `describe`) — producer community-rewards-engineer (`moderation/service.py`)
For `task_type = "hazard_insufficient_data"` only, `subject` gains:
```json
"missing_dimensions": [{ "code": "safety.health_safety", "name": "Health & Safety" }],
"passport_version": 7 | null
```
from `payload.missing_dimensions` (names from `hazard_dimensions`) and the version of `payload.passport_id`.
A task created before DEF-032 has no `missing_dimensions` in its payload: send `[]`. No other task type changes.
Staff-only, as today.

## D. `GET /api/v1/rewards` — producer community-rewards-engineer (`rewards/router.py`)
Each `ways_to_earn[]` item gains `"available": bool`. `false` for earns no member can perform today:
`photo` (WO-007, W4), `level2_verified` (WO-010), `referral` (phase two). `true` otherwise. Labels change
(copy only): `level1_verified` → "Verify your email" (D4); `login_streak` → "Sign in each day";
`login_streak_7plus` → "Sign in each day from day 7 of a streak". The streak amounts come from `coin_earn_rules`
as today; no amount changes.

## E. `GET /api/v1/products` — producer catalogue-engineer (`catalogue/router.py`, `service.search`)
New optional query parameter `screened: bool = false`. When `true`, only products whose current passport is tier 2
(a completed screening) are returned. Default behaviour unchanged. Used by the home page's "Recently screened".

## Unchanged
Everything else, including CT-001, CT-002, auth on every route, status codes and the passport cache key (the
24-hour cache may serve a passport without `recall_checked_as_of` until it expires or is re-screened: consumers
handle `null`/absent).

A frozen contract changes only by an amendment section added by tech-lead.
