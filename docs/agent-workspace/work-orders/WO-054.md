# WO-054 — Raw copies outside the database (S3) for ingestion

Owner: data-ai-engineer · Contract: none · Gate: qa-test-engineer + security-auditor (AWS access path) · Opened 2026-11-22 by tech-lead
Status: OPEN · Size S

## Why
Tech doc §15.3 week 2 (developer B): the job runner keeps raw copies in object storage. Today the raw payload
lives only in `source_records.payload`; `source_records.payload_storage_key` exists and is never set. PLAN WO-028
(W3) covers raw copies for barcode and vision lookups, not this. Not moved by the plan, so it is W2.

## Scope
- One provider client file (e.g. `backend/app/modules/ingestion/raw_store.py`) — the only code that talks to the
  raw store. Settings `RAW_STORE` (`none` default = today's behaviour; `s3`) and `RAW_BUCKET`, added in
  `core/config.py` (platform-identity-engineer's file: report the 2 lines, tech-lead routes them — or, if the
  setting fits beside `media_store`, list it under Needs).
- CPSC ingestion and research (`ingestion/service.py:86`, `research/service.py:213`): when `RAW_STORE=s3`, put
  the exact bytes fetched under `raw/<source>/<yyyy>/<mm>/<dd>/<sha256 hex>.json` (private, SSE-S3) and set
  `payload_storage_key`; the DB copy stays as it is. A failed upload is logged and counted, never loses the row.
- Tests with the client replaced wholesale: key set when `s3`, not set when `none`, upload failure keeps the row.

## Out of scope
Any AWS change: no bucket, no IAM edit, no env change on dev. Switching dev to `RAW_STORE=s3` is a human step
(WO-054 `## Blocked on human`). Barcode/vision raw copies (WO-028, W3).

## Acceptance
- [ ] With `RAW_STORE=none` nothing changes (existing tests green).
- [ ] With `RAW_STORE=s3` and the fake client, each new `source_records` row has `payload_storage_key` and the
      stored bytes hash to `payload_sha256`; a repeat payload stores nothing.
- [ ] Gates green; revert proof on the key-setting line.

## Blocked on human
Enabling on dev: (1) confirm the dev host role's S3 policy allows `s3:PutObject` on `raw/*` of the existing raw
bucket (it already writes `backups/postgres/*` there); if it is scoped to `backups/*`, add `raw/*` to it;
(2) set `RAW_STORE=s3` and `RAW_BUCKET` in the host's environment through `deploy-host.sh`; (3) push.
Cost: S3 Standard at roughly a few MB of JSON a month — under $0.05/month; PUT requests ~ $0.005 per 1,000.
