# WO-009 — Pipeline: tests on every push, release to dev from main, browser tests

Owner: (single session) → qa-test-engineer · Opened 2026-11-15
Status: DONE-PENDING-QA · Size M

## Why
The human asked for the whole flow to be tested end to end and for an end-to-end CI/CD pipeline through `main`.

## Scope
`.github/workflows/pipeline.yml`; `e2e/` (Playwright: `journey.spec.ts` against a full local stack,
`smoke.spec.ts` read-only against a deployed site); the hosts' deploy agents and their setup scripts under
`infra/aws/`; `/health` reporting the commit.

## Acceptance
- [x] A push with a failing test does not release: the first run failed two jobs and skipped the release.
- [x] A green push to `main` is live on both hosts without anyone touching AWS, and the run checks the live site.
- [x] The workflow holds no cloud credentials.

## Log
- 2026-11-16: built in one session. The usual route, GitHub assuming an AWS role, is closed: the account's
  organisation policy denies creating the identity provider (`iam:*OpenIDConnectProvider*`, explicit deny in a
  service control policy). That block was not worked around and no access keys were made. The release is
  pull-based instead: the workflow commits the web build and a `VERSION` file to `release/dev`; a systemd
  timer on each host polls that branch and deploys.
- Found by the first run, fixed: `make db-test` assumed the database image already existed (it does on a
  developer's machine, not on a fresh runner); the newest runner image is not supported by the pinned
  Playwright, so the two browser jobs are pinned to `ubuntu-24.04`.
- Found by writing the journey test: nothing in the product. One assertion of mine was too loose.
- Side effect on the developer machine: installing Playwright removed an unused `ffmpeg` build from the shared
  browser cache. Another project that needs it will download it again on its next `playwright install`.
- Consequence to know: anyone who can write to `release/dev` can deploy to dev. The branch is not protected
  (that needs the repository's owner).
