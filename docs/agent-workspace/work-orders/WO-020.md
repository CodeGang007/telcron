### DEF-006 item 1 — the budget notifies nobody (USD 0.00 a month)
Repo today: `docs/runbooks/aws-dev.md:158` (budget `telcron-monthly`, USD 22, no subscriber) and `:192`
(known gap). No file in `infra/` creates or changes the budget. Decision needed: **who** is the named
recipient (one email address).

```bash
aws login
aws budgets create-notification --account-id <account id> --budget-name telcron-monthly \
  --notification NotificationType=ACTUAL,ComparisonOperator=GREATER_THAN,Threshold=80,ThresholdType=PERCENTAGE \
  --subscribers SubscriptionType=EMAIL,Address=<named person's email>
aws budgets create-notification --account-id <account id> --budget-name telcron-monthly \
  --notification NotificationType=FORECASTED,ComparisonOperator=GREATER_THAN,Threshold=100,ThresholdType=PERCENTAGE \
  --subscribers SubscriptionType=EMAIL,Address=<named person's email>
aws budgets describe-notifications-for-budget --account-id <account id> --budget-name telcron-monthly   # check
```
Cost: a cost budget without actions and its email notifications are free. Note: the runbook's estimate is
about USD 23 a month against a USD 22 budget, so the forecast alert will fire this month. Either accept
that, or raise the budget (`aws budgets update-budget`, also free) — the human's call.
After it is done: runbook row `aws-dev.md:158` gets "alerts at 80 % actual and 100 % forecast to the named
person", and the gap at `:192` is removed.

### DEF-006 item 2 — Lightsail port 22 open to the internet (USD 0.00 a month)
Repo today: `infra/aws/setup-web-host.sh:66` only lists listening ports; no file manages the Lightsail
firewall. `aws-dev.md:189` records 22 open; `aws-dev.md:75` says the host is reached by SSH with the
account's Lightsail key. Releases do not use 22: `infra/aws/agent-web.sh` pulls from GitHub.
Two readings; I would pick **A**, because it keeps the console's browser SSH for emergencies and closes
22 to everyone else.

```bash
aws login
aws lightsail get-instance-port-states --instance-name telcron-dev-web   # before: expect only 22, 80, 443
# A (recommended): 22 only from Lightsail's browser-SSH service. put-... REPLACES the whole set.
aws lightsail put-instance-public-ports --instance-name telcron-dev-web --port-infos \
  'fromPort=80,toPort=80,protocol=tcp,cidrs=0.0.0.0/0,ipv6Cidrs=::/0' \
  'fromPort=443,toPort=443,protocol=tcp,cidrs=0.0.0.0/0,ipv6Cidrs=::/0' \
  'fromPort=22,toPort=22,protocol=tcp,cidrListAliases=lightsail-connect'
# B: close 22 entirely — the same command without the third entry. To reopen for a session:
#   aws lightsail open-instance-public-ports --instance-name telcron-dev-web \
#     --port-info 'fromPort=22,toPort=22,protocol=tcp,cidrs=<your address>/32'
aws lightsail get-instance-port-states --instance-name telcron-dev-web   # after
curl -fsS "$DEV_WEB_URL/version.txt"                                     # the site still answers
```
If the "before" state lists any port other than 22, 80 and 443, stop: `put` would close it. After it is
done: `aws-dev.md:75` and `:189` are updated (SSH from a laptop no longer works under A).

### DEF-006 item 4 — the backend image is built on the host (USD 0.00 a month on AWS)
Repo today: `infra/aws/deploy-host.sh:49-53` builds the image when `BACKEND_IMAGE` is unset, and
`agent-backend.sh` never sets it, so every release builds on the 2 GB host. `deploy-host.sh:147-151` can pull
only from ECR, which needs AWS credentials to push to — and GitHub holds none (organisation policy). ECR
`telcron/backend` (`aws-dev.md` inventory) is unused.
Prepared change, no AWS resource involved: GitHub's own registry. The repository is public, so a public
package can be pulled by the host with no credential at all; the image holds only `backend/app`,
`pyproject.toml`, `uv.lock` (`backend/Dockerfile:13,16`), nothing secret.
1. `.github/workflows/pipeline.yml` (mine; not applied until 2 and 3 are agreed), a new job, and `image`
   added to `release.needs`:
   ```yaml
     image:
       name: Backend image (arm64)
       if: github.event_name == 'push' && github.ref == 'refs/heads/main'
       needs: [deps, schema, backend, frontend, e2e]
       runs-on: ubuntu-24.04-arm          # native arm64, free for public repositories
       permissions:
         contents: read
         packages: write
       steps:
         - uses: actions/checkout@v4
         - name: Build and push
           env:
             TOKEN: ${{ github.token }}
           run: |
             img="ghcr.io/${GITHUB_REPOSITORY_OWNER,,}/telcron-backend:${GITHUB_SHA}"
             printf %s "$TOKEN" | docker login ghcr.io -u "$GITHUB_ACTOR" --password-stdin
             docker build --build-arg GIT_SHA="$GITHUB_SHA" -t "$img" backend
             docker push "$img"
   ```
2. Human, once, in GitHub (outward-facing): after the first push, the package `telcron-backend` →
   Package settings → visibility **Public**.
3. `infra/aws/deploy-host.sh` (lines to come from the other WO, not edited here): when `BACKEND_IMAGE` is
   unset, `docker pull ghcr.io/<owner>/telcron-backend:$GIT_REF` and use it; build locally only if the
   pull fails.
Cost: AWS USD 0 (inbound transfer is free; no ECR use). GitHub: public packages and arm64 runners for
public repositories are free. Optional later, with a yes: delete the unused ECR repository `telcron/backend`
(saves its storage, a few cents a month).
