# WO-002 — Deploy dev to AWS

Owner: infra-deploy-engineer → security-auditor · Opened 2026-11-15
Status: OPEN · Size M

## Why
The hosts exist and are empty. Telcron needs a URL to look at.

## Scope
`backend/Dockerfile`; `infra/compose.aws.yml` running API, Worker and Redis on the EC2 host; image pushed to ECR
`telcron/backend`; migrations and reference seed against RDS; Caddy or nginx on the host for TLS; the built
frontend served by nginx on the Lightsail host with `VITE_API_URL` pointing at the API. Deploy through SSM, not SSH.

## Out of scope
Auto-scaling, a load balancer, a second environment, a domain name (ask the human).

## Acceptance
- [ ] `GET /health` on the EC2 host returns ok over HTTPS.
- [ ] The web app on Lightsail completes sign-up to passport against the deployed API.
- [ ] `ENV` is not `local`; `DEV_EXPOSE_CODES` is off; the seeded admin does not exist; demo products are not seeded.
- [ ] The EC2 role can read the RDS-managed secret (`rds!db-…`), which its current policy does not cover.
- [ ] `docs/runbooks/aws-dev.md` updated in the same change.

## Blocked on human
Where PostgreSQL runs (RDS, or Docker on the EC2 host) decides the compose file and the cost: see
`docs/runbooks/aws-dev.md`. And: with codes not sent (WO-005) nobody can finish sign-up on a deployed build. Either WO-005 lands first, or the
human accepts a temporary allow-list. Recommended: WO-005 first.
